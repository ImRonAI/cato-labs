Page: /capabilities/ai-agent-systems ("AI & Agent Systems")
Status as of 2026-10-19: the scroll journey (section 3) and the voice dock (step 1-3: bubble, Talk to Cato, mode/tool/approval events, lip-sync from output volume) are built and tested in the real UI. Cato is the owner's Timmy rig (generated by scripts/gen-cato-core.mjs, drawn in three.js), including its cards and emotes. /api/music is built and tested (one live generation, audio/mpeg). 1. WHAT THE AGENT HAS (AND DOES NOT HAVE)

The agent gets exactly two MCP servers and no other tools.

MCP server 1: Oubliai Telnyx
- URL: https://oubli-catolabs.fastmcp.app/mcp
- Transport: Streamable HTTP.
- Authentication: a Horizon API key, sent as a Bearer token. It is held in an ElevenLabs auth connection. The key was verified live: initialize returned HTTP 200, with serverInfo "Oubliai Telnyx" 4.1.0.
- Tools it exposes, as listed live:
  - tags, search, get_schema, execute. These are discovery tools plus a code runner over 1,386 Telnyx operations.
  - generate_prefab_ui and search_prefab_components. These build visual UI that the page can render. The SDK has an onRichContent callback; how prefab output reaches the page is UNVERIFIED and must be live-tested.
- Telnyx operations confirmed to exist, which the agent runs through execute:
  - Calls: DialCall, SpeakCall, HangupCall
  - Text messages: SendMessage
  - Email: CreateEmailMessage
  - Fax: SendFax
  - Video rooms: CreateRoom, CreateRoomClientToken
- Recommended approval setting: Fine-Grained.
  - Auto-approve tags, search and get_schema.
  - Require approval for execute.

MCP server 2: ElevenLabs hosted MCP
- URL: https://api.elevenlabs.io/v1/mcp
- Authentication: OAuth only. A live probe returned "OAuth bearer token required for the hosted MCP".
- What ElevenLabs' docs say it offers:
  - Agent management: create, update, delete and deploy agents.
  - Conversations, tests, knowledge base and triage.
  - Text-to-speech, returned as a short-lived download link.
- UNVERIFIED: whether it has a music tool. The hosted-MCP docs page does not list one.
- Recommendation: disable every agent-management, test, knowledge-base and conversation-reading tool on this server. The system prompt already forbids them.

Client tool:
- `next_stop` (plus `previous_stop` and `go_to_stop`, with an optional `stop` parameter 1–9 or stop id): moves Cato to the next stop on the tour when the visitor asks. Plays Cato's 6-second fall on a timer, scrolls the page to that stop's copy, and returns the stop's title and body to the agent.
- No webhook tools, such as a separate saveLead. Leads go out by email through Telnyx CreateEmailMessage to hi@cato-labs.com.

Voice: model eleven_v4_turbo. This is a valid TTSConversationalModel value in the ElevenLabs OpenAPI spec, and it is the default.
Text normalization: "elevenlabs". The docs say it is more reliable than the system_prompt option for numbers and email addresses.
Dynamic variables used in the prompt: {{system__time}}, {{system__timezone}} and {{system__conversation_id}}. ElevenLabs fills these itself. The page passes the visitor's browser timezone when it starts the session.


2. THE VISITOR JOURNEY, STEP BY STEP

Step 0: page load (no agent yet)
- The page renders server-side with the nine capability sections as real, crawlable text, so search engines can read them.
- The persistent WebGL scene loads behind the page.
- The Cato character is an SVG overlay in the page DOM, ported from Timmy.html and recoloured to Cato blue and white. It idles.

Step 1: proactive greeting, at about 3 seconds
- Cato waves. A classic cloud thought bubble shows a short text greeting and a "Talk to Cato" button.
- Nothing plays audio and the microphone is not opened yet. Browsers block audio playback and microphone access until the visitor interacts with the page (autoplay policy). This is a hard browser limit, not a design choice.

Step 2: the visitor taps "Talk to Cato"
- The browser asks for microphone permission.
- The page starts the ElevenLabs conversation with @elevenlabs/react (installed, 1.18.0).
- Session start is one of two options, which the owner must pick:
  a) Public agent: the browser connects with the agent ID only. Lock it down with the agent's allowlist of site domains (the allowlist field exists in the OpenAPI spec).
  b) Private agent: a small server route on the site, /api/agent-session, calls GET /v1/convai/conversation/token using ELEVENLABS_API_KEY (already in .env.local). The browser then connects with that short-lived token.
- The agent speaks its first message.

Step 3: conversation and discovery
- The visitor talks, and Cato answers questions about Cato Labs using only the facts in the system prompt.
- The page drives the character from SDK events. All of these callback names were confirmed in node_modules/@elevenlabs/client:
  - onModeChange (speaking / listening): the talk or listen-idle animation.
  - Lip-sync as built: getOutputVolume() sampled every frame drives Cato's mouth. (onAudioAlignment, unused for now: character timings, The SDK code calls it whenever an audio event carries alignment. UNVERIFIED: that ElevenLabs sends alignment for this agent and transport. This must be live-tested. The fallback is HeadAudio, which works out mouth shapes from the output audio itself.
  - onMCPToolCall: the tool-call state. When the operation is a call, text, email, fax or video room, the matching prop scene plays (phone, texting, desk/email, fax, video).
  - Approvals as built: @elevenlabs/react 1.18 has no onMCPToolApprovalRequest option on the hook, so the page catches onMCPToolCall with state "awaiting_approval", shows an Approve / Deny card, and answers with sendMCPToolApprovalResult(tool_call_id, approved).
  - onError / onDisconnect: Cato's "something went wrong" pose, and the "Talk to Cato" button comes back.
- Meanwhile the visitor can keep scrolling. Scrolling is never controlled by the agent.

Step 4: live demonstration (the visitor asks for one)
- Cato collects the visitor's own phone number or email, reads it back, and waits for a clear yes.
- Cato says what he is about to do.
- The tool sequence on the Telnyx server:
  1. search, to find the operation, plus the operations that list the account's phone numbers, connections, messaging profiles or email domains.
  2. get_schema.
  3. execute, which raises an approval request.
  4. The visitor taps Approve on the page.
  5. The Telnyx action runs.
- The visitor's phone rings, or a text, email, fax or video-room link arrives.
- Cato confirms only what the tool result confirms. If Telnyx returns an error, he explains it in one sentence. The server passes Telnyx errors through unmasked.
- Account prerequisites, outside this site, on the Telnyx account behind the Horizon server. Each demo works only if its resource exists:
  - Calls: a voice-enabled number and connection.
  - Texts to US numbers: 10DLC registration.
  - Email: a verified sending domain.
  - Fax: a fax-capable connection.
  - Video: Rooms enabled.

Step 5: lead capture
- Cato offers to pass the request to the team, then collects the visitor's name, how to reach them, their business and what they want built.
- execute runs CreateEmailMessage to hi@cato-labs.com. This also needs approval. The email includes a summary and the conversation ID.
- If it fails, Cato says so and points the visitor to the site's contact form.

Step 6: end
- The visitor ends the session or closes the page. Cato returns to idle and the "Talk to Cato" button stays available.


3. THE NINE-STOP JOURNEY (button- and voice-triggered falls; never triggered by scroll)

- Nine stops, each a normal 100vh section (`JOURNEY_STOP_VH = 100`). The section ids are fixed:
  1. omnichannel
  2. entertainment
  3. tooling
  4. automation
  5. frameworks
  6. seo-marketing
  7. lead-gen
  8. lead-qualify
  9. support-compliance
- On each ledge, Cato waits in idle until a real event occurs (a tool call, a DJ track playing, or a tool being built).
- Cato's fall to the next ledge is NEVER triggered by trackpad or wheel scrolling. It starts only when:
  1. The visitor clicks the on-page "Next stop" (or "Previous stop") button on a stop (`JourneyNav.tsx`), OR
  2. The voice agent calls the `next_stop` (or `previous_stop` / `go_to_stop`) client tool during a voice tour (`CatoVoice.tsx`).
- When triggered, the fall plays on a 6-second timer (`FALL_SECONDS = 6`: take-off trick leap, free-fall trick with cartwheel and wind streaks, and landing with shockwave ring), and the page smoothly scrolls to the target stop's copy with him.
- Reduced motion: Cato holds a static pose on the active ledge and stop navigation jumps without the fall animation.
- If a voice session is active when the visitor clicks "Next stop", the page sends the agent a contextual update (`sendContextualUpdate`) naming the stop and its copy.

Stops with extra page-side features (independent of the agent's tools):
- entertainment: music generated by the site's server through the ElevenLabs Music streaming API, using ELEVENLABS_API_KEY. The SDK method is music.stream with prompt, music_length_ms and model_id "music_v2_5" (from ElevenLabs' streaming guide). Cato dances in time to it.
  - The docs state the Music API requires a paid ElevenLabs plan.
  - This runs outside the agent, as a site feature.
- tooling: Cato builds the tool with generate_prefab_ui on the Telnyx server (no Perplexity, no extra service). The page will render the result with the official MCP Apps host (AppBridge from @modelcontextprotocol/ext-apps 2.0.3, reusing the TelnyxMCP packages/app host). NOT BUILT YET. Open items: the MCP Apps sandbox page must be served from a separate origin; reading the ui://prefab/generative.html resource needs a server-side MCP connection; and whether onMCPToolCall's result carries structuredContent is UNVERIFIED until the agent exists.


4. BACKGROUND PROCESSES AND SERVER PIECES

Runs on ElevenLabs:
- The agent itself: the LLM, ASR, eleven_v4_turbo TTS and turn-taking.
- The MCP connections to both servers, the approval policy, and pre-tool speech.

Runs on Prefect Horizon:
- The Oubliai Telnyx FastMCP server. It is already deployed. Each operation calls the Telnyx REST API.

Runs on the Cato Labs site (Next.js):
- The page: server-rendered sections, the WebGL scene, the Cato SVG overlay, and the scroll choreography.
- The SDK event handlers listed in step 3 (animation, lip-sync, approval card).
- Only if a private agent is chosen: /api/agent-session, which mints the conversation token.
- /api/music, the Eleven Music streaming proxy for the entertainment stop.
- No database, no queue, no WebSocket relay, and no extra servers.

Secrets:
- ELEVENLABS_API_KEY is in the site's .env.local and is used only by the site's server routes.
- The Horizon key is stored only in the ElevenLabs auth connection.
- No secret reaches the browser.
